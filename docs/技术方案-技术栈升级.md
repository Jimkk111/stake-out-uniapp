# 瑞吉外卖用户端 · 技术栈升级技术方案

> 版本：v1.0（2026-09-06）
> 约束：**继续使用 HBuilderX 开发，不迁移 CLI 工程**；后端接口（黑马演示环境 `/shoppingCart` + `/order/submit` 体系）保持不变，仅升级前端技术栈与代码结构。

---

## 1. 背景与现状

### 1.1 项目现状

| 项 | 现状 |
|---|---|
| 工程形态 | HBuilderX 项目，无 package.json，编译器随 HBuilderX 内置 |
| 框架 | uni-app，Vue 2（Options API），compilerVersion 3 |
| 状态管理 | Vuex 单文件（`store/index.js`），仅 mutations、无 modules、无持久化 |
| 网络请求 | `uni.request` 自封装（`utils/request.js`），Cookie 手工携带 `JSESSIONID` |
| 实时通信 | STOMP over WebSocket，`utils/stomp.js` 为 2013 年 CoffeeScript 编译的远古版本 |
| 样式 | SCSS（dart-sass），页面级 style.scss + `uni.scss` 全局变量 |
| UI 组件 | 手拷贝旧版 uni-icons / uni-nav-bar / simple-address，无 easycom |
| 登录 | `uni.getUserProfile`（微信官方已废弃）+ `uni.login` |

### 1.2 现状问题清单（升级动因）

1. **Vue 2 已 EOL**（2023-12-31），不再有安全与 bug 修复；uni-app 官方主推 Vue 3 + Vite 编译链。
2. `uni.getUserProfile` 被微信废弃，当前登录拿不到真实昵称头像。
3. 登录态（sessionId）存 Vuex 内存，**无持久化**，杀掉小程序即失效，每次都要重新授权。
4. 新旧两套接口并存（堂食扫码点餐遗留 + 外卖现行），大量注释死代码（约 40% 的 js 行数为注释）。
5. `mapState`/`mapMutations` 被当函数调用（`this.orderListData()`）的反常规写法，遍布各页面。
6. 根目录存在整份工程拷贝（`mp-weixin/`），非 git 仓库，无版本管理。
7. `stomp.js` 远古版本存在已知兼容/安全问题；多人点餐推送（WebSocket 模块）在现行外卖流程中**未启用**。

### 1.3 目标

- Vue 2 → **Vue 3**（Vite 编译），Vuex → **Pinia**，登录态持久化，微信登录方式现代化。
- 代码结构收敛：接口/请求/状态/组件分层清晰，删除死代码与冗余拷贝。
- **交付物保持可用**：分阶段推进，每阶段结束均可编译、可回归、可停在任何节点。

### 1.4 兼容性摸底结论（已完成）

| 检查项 | 结论 |
|---|---|
| `/deep/` 深度选择器 | 共 3 处，**已修复**为 `::v-deep`（dart-sass 兼容） |
| `$on/$off` 事件总线 | 无使用（Vue 3 移除，无阻塞） |
| filters 管道 | 无使用（Vue 3 移除，无阻塞） |
| 自定义组件上的 `v-model` | 无使用，仅原生 input/textarea（Vue 3 兼容） |
| scss 裸除法 | 无使用 |
| nvue | 仅 `simple-address.nvue` 一个文件，未被 pages.json 注册为页面 |

## 4. 详细设计

### 4.1 应用入口（Vue 3）

```js
// main.js
import { createSSRApp } from 'vue'
import App from './App.vue'
import * as Pinia from 'pinia'

export function createApp() {
  const app = createSSRApp(App)
  app.use(Pinia.createPinia())
  return { app, Pinia }   // uni-app Vue3 要求返回 Pinia 引用
}
```

`App.vue` 移除现有 template 相关兼容代码（本项目本无 template，仅保留 `<style>`；全局启动逻辑在 `onLaunch` 中初始化登录态恢复，见 §4.4）。

### 4.2 环境配置

```js

export const baseUrl = isDev
  ? 'https://reggie-dev.itheima.net'   // 待替换为自建后端
```

现状 `utils/env.js` 是硬编码单值，升级后开发/生产分离，且 dev 值需在联调前确认后端可用性。

### 4.3 请求层重写（utils/request.js）

职责与语义：

1. **入参**：`{ url, params, method }`，与现有 api 函数签名一致，`api/index.js` 不需要大面积改动。
2. **鉴权注入**：自动从 `stores/user` 读 sessionId，拼 `Cookie: JSESSIONID=...`；无登录态时直接 reject（触发重新登录），不再发无效请求。
3. **响应判定**：`code === 1 || code === 200` 视为成功（与后端现状一致）。
4. **错误处理**：失败统一 `uni.showToast`（保留调用方 catch 覆写的能力），替换现在各页面几十处空 `catch (err) {}`。
5. **登录失效**：识别 401 / session 失效响应 → 清空 user store → 跳转首页重新登录（复用现有 `nonet` 页处理网络错误，登录失效走独立路径）。

```js
// utils/request.js（骨架）
import { baseUrl } from '@/config/env'
import { useUserStore } from '@/stores/user'

export function request({ url = '', params = {}, method = 'GET' }) {
  const userStore = useUserStore()
  if (!userStore.sessionId) return Promise.reject({ code: 401, msg: '未登录' })
  return new Promise((resolve, reject) => {
    uni.request({
      url: baseUrl + url,
      data: params,
      method,
      header: {
        'Content-Type': 'application/json',
        Cookie: 'JSESSIONID=' + userStore.sessionId,
      },
      success: (res) => {
        const { data } = res
        if (data.code === 1 || data.code === 200) return resolve(data)
        if (isSessionExpired(data)) {          // 按后端实际失效码适配
          userStore.logout()                   // 清登录态 + 清 storage
          uni.reLaunch({ url: '/pages/index/index' })
        }
        reject(data)
      },
      fail: (err) => reject({ code: -1, msg: '网络异常', data: err }),
    })
  })
}
```

### 4.4 登录与鉴权设计（微信 API 现代化）

现状问题：`uni.getUserProfile` 已废弃，只能返回匿名数据（灰色头像 / "微信用户"）。

目标方案（符合微信 2022+ 规范）：

1. **code 登录**：`uni.login` 获取 code → `POST /user/login`（沿用现有后端契约，`phone: jsCode` 字段名暂不动，后端适配后更名）→ 后端返回 `sessionId` → `setStorageSync('sessionId')` + Pinia。
2. **头像昵称**：改用官方"头像昵称填写能力"：
   - 头像：`<button open-type="chooseAvatar" @chooseavatar="onChooseAvatar">`
   - 昵称：`<input type="nickname">`（键盘上方出现"使用微信昵称"快捷项）
3. **启动免授权**：`App.vue onLaunch` 中从 storage 恢复登录态到 Pinia；首页 `onShow` 判 `sessionId` 存在则直接 `init()`，不存在才弹授权引导。
4. **手机号快捷登录**（可选增强）：`open-type="getPhoneNumber"` 需企业主体资质，列为后续项，不在本期。

### 4.5 状态管理设计（Pinia）

```js
// stores/user.js
import { defineStore } from 'pinia'

const KEY_SESSION = 'session_id'
const KEY_USER = 'base_user_info'

export const useUserStore = defineStore('user', {
  state: () => ({
    sessionId: uni.getStorageSync(KEY_SESSION) || '',
    baseUserInfo: uni.getStorageSync(KEY_USER) || null,
  }),
  actions: {
    setSession(id) {
      this.sessionId = id
      uni.setStorageSync(KEY_SESSION, id)
    },
    setUser(info) {
      this.baseUserInfo = info
      uni.setStorageSync(KEY_USER, info)
    },
    logout() {
      this.sessionId = ''
      this.baseUserInfo = null
      uni.removeStorageSync(KEY_SESSION)
      uni.removeStorageSync(KEY_USER)
    },
  },
})
```

```js
// stores/cart.js（收编页面里重复的金额/数量计算）

export const useCartStore = defineStore('cart', {
```

迁移要点：

### 4.6 页面与组件

- **easycom**（`pages.json`）：`"easycom": { "autoscan": true, "custom": { "^uni-(.*)": "@/components/uni-$1/uni-$1.vue" } }`，去掉各页面的手动 import。
- **uni-icons / uni-nav-bar**：删除 `components/` 下手拷贝旧版，从插件市场以 uni_modules 引入最新 Vue 3 兼容版。
- **simple-address**：`simple-address.nvue` → `simple-address.vue`（目标端仅微信小程序，nvue 无意义），或直接引入插件市场新版城市选择器并删除自带 city-data。
- **Navbar**（`pages/common/Navbar`）：保留，内部 `wx.getMenuButtonBoundingClientRect()` → `uni.` 前缀。

### 4.7 样式

- dart-sass 迁移已完成（`/deep/` → `::v-deep`，3 处）。
- 颜色/字号变量收敛到 `uni.scss`（现状各页面散落硬编码 `#ffc200`、`#333333` 等）。
- `@import` → `@use` 迁移：dart-sass 尚未强制，**列为后续项**，不在本期（避免扩大回归面）。

### 4.8 WebSocket / STOMP 模块（决策）

**决策：移除。** 理由：

1. 该模块服务"堂食扫码多人同桌点餐"（按 tableId 订阅 RabbitMQ `/exchange/micro_app_exchange/{tableId}`），现行外卖配送流程**没有任何调用启用它**（`initWebScoket` 的引用在旧方案注释代码中）。
2. 后端对应的 MQ 基础设施（socket-canzg.itheima.net，guest/guest）属演示环境，不具生产价值。
3. 若未来确实要恢复多人点餐/订单状态推送，再引入 `@stomp/stompjs` v7 + `uni.connectSocket` 适配器（HBuilderX Vue3/Vite 项目支持 npm），成本约 1 天，且届时应携带鉴权而非 guest/guest。

## 6. 回归测试清单（每阶段执行）

1. 冷启动 → 授权登录 → 首页分类与菜品加载
2. 菜品详情弹窗 → 规格选择（必选校验）→ 加购
3. 购物车加/减/清空 → 底部结算栏金额与数量正确
4. 提交订单：默认地址回显 → 修改地址 → 备注 → 提交成功页
5. 地址管理：新增/编辑/删除/设默认 → 返回订单页回显正确（跨页传参）
6. 历史订单：分页加载、下拉刷新、再来一单
7. 个人中心信息展示
8. 断网 → 无网络页 → 恢复网络返回
9. **持久化专项**：下单中途杀掉小程序重进，登录态与购物车（后端侧）仍有效
